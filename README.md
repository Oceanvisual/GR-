# AI-анализ НПА

Веб-сервис для GR-специалиста. Он загружает нормативный правовой акт (административный регламент,
закон, приказ, постановление) и строит структуру документа с реквизитами. Затем LLM извлекает
из текста бизнес-процессы, и сервис предлагает инициативы по автоматизации с экономикой и
рейтингом. Каждый факт подтверждён цитатой из акта со ссылкой на пункт; всё числовое считает
детерминированный код, не LLM.

Постановка, план и решения — в [`specs/001-npa-ai-analyzer/`](specs/001-npa-ai-analyzer/):

- [spec.md](specs/001-npa-ai-analyzer/spec.md) — требования;
- [plan.md](specs/001-npa-ai-analyzer/plan.md) — архитектура;
- [research.md](specs/001-npa-ai-analyzer/research.md) — решения R-01…R-22;
- [data-model.md](specs/001-npa-ai-analyzer/data-model.md) — модель данных;
- [contracts/api.md](specs/001-npa-ai-analyzer/contracts/api.md) и
  [contracts/ui.md](specs/001-npa-ai-analyzer/contracts/ui.md) — API и экраны;
- [quickstart.md](specs/001-npa-ai-analyzer/quickstart.md) — сценарии проверки Q1–Q19.

Развёртывание на сервере описано в [docs/deploy.md](docs/deploy.md).

## Что умеет

**Форматы.** Сервис принимает:
- DOCX, PDF с текстовым слоем, TXT в любой кириллической кодировке, HTML-страницы;
- DOC, RTF и ODT — через LibreOffice;
- сканированные PDF — распознаются tesseract в фоне, с прогрессом и качеством по страницам.

Многоколоночные PDF читаются колонка за колонкой. Служебные строки справочных систем и пометки
редакции вынимаются из текста.

**Структура.** Сервис распознаёт разделы, главы, «§», статьи с частями, пункты, подпункты,
абзацы, утверждаемые документы и приложения. Метки фрагментов — как в юридическом тексте
(«п. 2 ч. 3 ст. 5»). Профиль нумерации (закон или регламент) выбирается автоматически. Если
нумерации нет, структура строится по оформлению или по абзацам, с оценкой уверенности.

**Анализ на LLM** (OpenAI-совместимый API) идёт в три этапа:
- S3 — процессы;
- S4 — операции с исполнителем, сроком и цитатой;
- S6 — инициативы автоматизации.

Цитаты проверяются по тексту, а инструкции внутри документа не исполняются.

**Расчёты без LLM.** Экономика инициатив по сценариям, Priority Score, портфель — с пересчётом
при изменении допущений.

**Экспертная проверка.** Решения эксперта, правки с историей, перегенерация инициатив процесса.

**Экспорт.** JSON и CSV.

## Локальный запуск

Нужны [uv](https://docs.astral.sh/uv/) и Python 3.12. Остальное — по необходимости:

```bash
brew install tesseract tesseract-lang     # OCR сканов (rus + eng)
brew install --cask libreoffice           # .doc, .rtf, .odt
```

Без tesseract сканы сохраняются со статусом «OCR недоступен». После установки распознавание
запускается кнопкой «Повторить распознавание». Без LibreOffice на DOC, RTF и ODT пользователь
получает просьбу сохранить файл в DOCX.

```bash
uv sync
cp .env.example .env    # настройки — переменные окружения; шаблон со всеми ключами в репозитории
uv run gr serve         # http://127.0.0.1:8000
```

Для локальной работы без входа укажите `APP_ENV=local` и `AUTH_ENABLED=false`. Данные
(SQLite, исходные файлы) лежат в `DATA_DIR` (по умолчанию `./data`).

### LLM

Передачу текста документа наружу задаёт `LLM_DATA_POLICY`:

| Политика | Что разрешено |
|---|---|
| `disabled` (по умолчанию) | Анализ недоступен. Загрузка, структура и реквизиты работают |
| `local_only` | Только endpoint на хостах из `LLM_LOCAL_HOSTS` (Ollama, vLLM в своей сети) |
| `external_allowed` | Любой OpenAI-совместимый endpoint, например OpenRouter |

Для анализа нужны `LLM_BASE_URL`, `LLM_MODEL_EXTRACTION` (S3, S4) и `LLM_MODEL_ANALYSIS` (S6).
Необязательный `LLM_MODEL_DISCOVERY` задаёт отдельную модель только для карты процессов (S3).
Ключ — в `LLM_API_KEY`. Примеры:

```bash
# OpenRouter — конфигурация, на которой снят baseline eval (evals/baseline.json)
LLM_DATA_POLICY=external_allowed
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL_EXTRACTION=anthropic/claude-haiku-5.5
LLM_MODEL_DISCOVERY=anthropic/claude-sonnet-5.5
LLM_MODEL_ANALYSIS=anthropic/claude-haiku-5.5

# Ollama на этой машине
LLM_DATA_POLICY=local_only
LLM_BASE_URL=http://localhost:11434/v1
LLM_MODEL_EXTRACTION=qwen3:32b
LLM_MODEL_ANALYSIS=qwen3:32b
LLM_STRUCTURED_MODE=json_object

# vLLM в своей сети (хост vllm входит в LLM_LOCAL_HOSTS)
LLM_DATA_POLICY=local_only
LLM_BASE_URL=http://vllm:8000/v1
LLM_MODEL_EXTRACTION=<имя модели в vLLM>
LLM_MODEL_ANALYSIS=<имя модели в vLLM>
```

`LLM_STRUCTURED_MODE` задаёт способ получения JSON: `json_schema`, `json_object` или `auto`
(по умолчанию). Стоимость запуска считается, если заданы `LLM_PRICE_INPUT_PER_MTOK` и
`LLM_PRICE_OUTPUT_PER_MTOK` (за 1 млн токенов) — один тариф на все вызовы запуска; счёт
провайдера из ответов (OpenRouter отдаёт `usage.cost`) точнее при разных моделях на этапах и
имеет приоритет. Этапы и рассуждение моделей настраиваются в
`src/gr/config/llm.toml`.

### Пользователи

Вход — HTTP Basic. Строку пользователя для `AUTH_USERS` даёт команда:

```bash
uv run gr hash-password --login expert   # спросит пароль дважды, выведет login:scrypt$…
```

Несколько пользователей перечисляются через запятую.

## Проверки

```bash
./scripts/check.sh      # ruff, ruff format, mypy strict, pytest — без сети, на FakeLLM; единственный гейт, его же запустит CI
```

Тесты с настоящим tesseract и LibreOffice помечены маркерами `ocr` и `soffice`. Если программ
нет, тесты пропускаются; в Docker-образе сервиса они выполняются.

Структура документов dev-корпуса сверяется со снимками `tests/fixtures/*/*.structure.json`.
После намеренного изменения разбора снимки обновляются командой
`UPDATE_SNAPSHOTS=1 uv run pytest tests/corpus`, и их diff читает человек.

Качество извлечения на живой LLM проверяет eval: [evals/README.md](evals/README.md). Его
запускают вручную перед мержем изменений промптов, моделей и разбора.

## Ограничения MVP

- Один процесс сервиса: фоновые анализы и OCR живут в нём; база — SQLite.
- Изображения (JPG, PNG, TIFF) не принимаются, только документы. Лимиты: 20 МБ, 300 страниц,
  1 млн знаков, OCR — до 150 страниц (`MAX_*`, `OCR_MAX_PAGES`).
- OCR распознаёт русский и английский текст. Рукописные пометки и штампы не распознаются.
  Дату и номер скана сервис ищет только в шапке рядом с видом акта. Если они вписаны от руки,
  поля остаются пустыми, их заполняют в «Исправить реквизиты». Таблицы на сканах распознаются
  с низкой уверенностью: такие страницы перечислены в диагностике.
- Повторить OCR после того, как по документу запускался анализ, нельзя. Иначе новый текст
  разошёлся бы с цитатами анализа.
- Оглавление в начале документа может дать в дереве повторные разделы.
- Качество извлечения процессов зависит от модели. Её выбирают по eval, а не по умолчанию.
